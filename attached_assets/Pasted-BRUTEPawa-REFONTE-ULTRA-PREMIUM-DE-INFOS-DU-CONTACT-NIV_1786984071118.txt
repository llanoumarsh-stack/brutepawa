1. COMPRENDRE LA PAGE AVANT DE CODER

Cette page représente :

«LES INFORMATIONS D'UN AUTRE UTILISATEUR / CONTACT»

Ce n'est PAS :

- la page de mon propre profil ;
- mon propre tableau de bord ;
- ma page de paramètres personnels ;
- une page de modification de profil.

Le propriétaire de la page est donc le contact consulté.

Toutes les informations affichées doivent appartenir à ce contact.

5. CARTE PRINCIPALE DU CONTACT

Créer une grande carte blanche premium.

Elle doit contenir :

Avatar

Afficher l'avatar réel du contact.

Si le contact n'a pas de photo :

utiliser son avatar généré à partir de ses initiales, comme dans la référence.

L'avatar doit avoir :

- forme parfaitement circulaire ;
- bordure verte BrutePawa ;
- anneau extérieur très subtil ;
- indicateur de présence correctement positionné.

Statut

Afficher le statut réel :

En ligne

si le contact est réellement en ligne.

Sinon afficher le statut approprié :

- En ligne
- Actif récemment
- Hors ligne

Ne jamais afficher « En ligne » de manière statique si le backend indique le contraire.

Omar Omar

Le nom doit être :

- fortement lisible ;
- centré ;

- noir / presque noir ;

Ne pas ajouter automatiquement :

- @username ;
- ID ;
- pays ;
- âge ;
- nombre d'abonnés ;
- nombre d'amis.

Ces informations ne doivent apparaître que si elles sont réellement prévues dans cette interface.

10. RÈGLE CRITIQUE SUR LES SOUS-PAGES

NE CRÉE PAS SIX SOUS-PAGES simplement pour remplir l'écran.

NE CRÉE PAS :

- page « Profil » supplémentaire ;
- page « Activité » ;
- page « Intérêts » ;
- page « Groupes communs » ;
- page « Médias partagés » ;
- page « Confidentialité » ;

si ces informations ne sont pas directement accessibles depuis la référence ou nécessaires au fonctionnement de l'élément concerné.

Principe :

«UNE LIGNE = UNE DESTINATION LOGIQUE.»

Si une ligne n'a pas besoin d'une sous-page :

SUPPRIMER LA FLÈCHE ET NE PAS CRÉER DE SOUS-PAGE.

Si une ligne nécessite une sous-page :

CRÉER UNE SOUS-PAGE SIMPLE, PREMIUM ET STRICTEMENT LIÉE À CETTE LIGNE.

Aucune page décorative.

Aucune navigation artificielle.

13. MENU TROIS POINTS

Le bouton "⋮" doit fonctionner.

Lorsqu'on appuie dessus, ouvrir un menu contextuel premium.

Le menu doit contenir uniquement les actions réellement disponibles pour un contact.

Les actions possibles selon les fonctionnalités existantes :

- Rechercher dans la conversation ;
- Partager le contact ;
- Bloquer ;
- Signaler ;
- Supprimer le contact.

IMPORTANT

Ne pas afficher une action si elle n'existe pas réellement dans BrutePawa.

Ne jamais créer des boutons « fictifs ».

14. BLOQUER LE CONTACT

Si l'action existe :

Afficher une confirmation avant blocage.

Titre :

Bloquer ce contact ?

Expliquer clairement la conséquence.

Actions :

Annuler

Bloquer

Après confirmation :

- le backend doit réellement enregistrer le blocage ;
- les appels doivent être traités conformément au blocage ;
- les messages doivent respecter le blocage ;
- l'interface doit refléter immédiatement le nouvel état.

32. RÈGLE SPÉCIALE POUR LES SOUS-PAGES

C'est extrêmement important :

NE CHERCHE PAS À REMPLIR L'APPLICATION AVEC DES SOUS-PAGES.

Une sous-page n'est créée que lorsqu'elle apporte une information ou une action nécessaire.

→ créer la sous-page.

→ ne pas créer de sous-page.

→ supprimer l'indicateur de navigation.

Une flèche ">" doit toujours avoir une destination réelle.
