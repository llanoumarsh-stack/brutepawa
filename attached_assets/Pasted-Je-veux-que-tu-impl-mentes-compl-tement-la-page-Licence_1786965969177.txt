Je veux que tu implémentes complètement la page « Licences et crédits » de BrutePawa.

OBJECTIF PRINCIPAL :

La page doit afficher automatiquement les technologies, bibliothèques, frameworks, packages, polices, icônes et autres ressources tierces réellement utilisés par le projet BrutePawa, avec leurs informations de licence.

IMPORTANT :
NE JAMAIS INVENTER une bibliothèque, une licence, un auteur, une version ou un crédit.

Toutes les informations affichées doivent provenir directement des fichiers et dépendances réellement présents dans le projet.

━━━━━━━━━━━━━━━━━━━━━━
1. ANALYSE COMPLÈTE DU PROJET
━━━━━━━━━━━━━━━━━━━━━━

Avant d'implémenter la page, analyse réellement le projet.

Inspecte notamment :

- package.json
- package-lock.json
- yarn.lock si présent
- pnpm-lock.yaml si présent
- bun.lock/bun.lockb si présent
- node_modules si disponible
- fichiers de configuration
- imports réellement utilisés dans le code
- assets
- polices
- bibliothèques d'icônes
- frameworks
- SDK
- composants open source
- dépendances natives
- dépendances Expo/React Native si présentes
- dépendances backend si présentes

Identifie les dépendances réellement utilisées par BrutePawa.

Ne te contente pas de lire uniquement package.json si certaines ressources sont utilisées autrement.

━━━━━━━━━━━━━━━━━━━━━━
2. INFORMATIONS À AFFICHER
━━━━━━━━━━━━━━━━━━━━━━

Pour chaque dépendance identifiée, afficher autant que possible :

- Nom
- Version réellement installée
- Auteur ou organisation
- Type
- Licence
- Lien officiel du projet
- Courte description
- Copyright lorsqu'il est disponible
- Texte de licence lorsqu'il est nécessaire de l'afficher

Exemple de présentation :

React

Bibliothèque utilisée pour construire l'interface de BrutePawa.

Version
19.x.x

Licence
MIT

Auteur
Meta Platforms, Inc.

Site officiel
[site officiel réellement trouvé dans les métadonnées du package]

Ne mets jamais une valeur fictive.

Si une information n'est pas disponible dans les métadonnées du package, affiche :

« Information non disponible dans les métadonnées du projet »

au lieu de l'inventer.

━━━━━━━━━━━━━━━━━━━━━━
3. DÉTECTION AUTOMATIQUE DES LICENCES
━━━━━━━━━━━━━━━━━━━━━━

Crée un système automatique permettant de détecter les licences des dépendances.

Utilise en priorité :

- les métadonnées package.json
- les fichiers LICENSE
- les fichiers LICENSE.md
- les fichiers COPYING

- BSD-2-Clause
- BSD-3-Clause
- ISC
- MPL
- GPL
- LGPL
- et toute autre licence réellement présente.

NE suppose jamais qu'une bibliothèque utilise MIT simplement parce qu'elle est populaire.

4. NE PAS INVENTER LES CRÉDITS
━━━━━━━━━━━━━━━━━━━━━━

C'est une règle ABSOLUE.

Interdiction de :

- créer de faux packages ;
- créer de faux auteurs ;
- inventer des licences ;
- inventer des versions ;
- inventer des liens ;
- ajouter des bibliothèques uniquement pour rendre la page plus remplie ;
- utiliser des exemples fictifs dans la production.

Chaque élément affiché doit pouvoir être relié à une dépendance ou une ressource réellement utilisée par BrutePawa.
